**# OWASP Top 10 (2025):**

**1. Broken access control :**

&#x09;- When user checks are missing, weak or only enforced on the client, attackers do things they shouldn't.

&#x09;- Viewing or modifying other users accounts.

&#x09;- Accessing sensitive data (like personal details or financial info).

&#x09;- Performing admin-level functions without authorization.

&#x09;- Scenario: Accessing another user’s account through URL parameters

&#x09;- Scenario: Accessing restricted admin pages

&#x09;- eg. Server side request forgery(SSRF)



**2. Security misconfiguration :**

&#x09;- When a system, application, or cloud service is set up incorrectly from a security perspective, creating vulnerabilities.

&#x09;- Application vulnerable if :

&#x09;	- Default admin accounts and password still active.

&#x09;	- Verbose error pages leaking stack traces in production.

&#x09;	- S3 bucket/cloud storage left world-readable.

&#x09;	- Debug endpoint exposed to internet.

&#x09;	- Outdated software with known CVEs.

&#x09;- Scenario : A cloud service provider (CSP) defaults to having sharing permissions open to the Internet. This allows sensitive data stored within cloud storage to be accessed.



**3. Software supply chain failure :**

&#x09;-  occurs when an application is compromised through its external dependencies, third-party libraries, developer tools, or CI/CD pipelines rather than the core application code.

&#x09;- Modern apps are 80% based on third party code

&#x09;- Malicious packages, typosquarts, hijacked maintainers.

&#x09;- Compromised build servers and CI Tokens.

&#x09;- Unpinned versions silently pulling in new code.

&#x09;- Plugins, extensions, base images and runners.

&#x09;- Scenario : A trusted vendor is compromised with malware, leading to your computer systems being compromised when you upgrade. The most famous example of this is probably: The 2019 SolarWinds compromise that led to \~18,000 organizations being compromised.



**4. Cryptographic failures :**

&#x09;**-** where weak, missing, or improperly implemented cryptography allows attackers to intercept, read, or alter sensitive information like passwords, financial details, and personal data.

&#x09;- application vulnerable if :

&#x09;	- Passwords stored as plane text or MD5/SHA-1.

&#x09;	- Data is transit over plain HTTP.

&#x09;	- Hard-coded keys in source code or mobile apps.

&#x09;	- Weak ciphers (DES, RC-4) and short keys still in use.

&#x09;	- Improper certificate validation.

&#x09;- Scenario : The password database uses simple hashes to store everyone's passwords. A file upload flaw allows an attacker to retrieve the password database. All the unsalted hashes can be exposed with a rainbow table of pre-calculated hashes. Hashes generated by simple or fast hash functions may be cracked by GPUs, even if they were salted.

&#x09;- prevention :

&#x09;	- hash password with Argon3id/bcrypt + per-user salt

&#x09;	- Use TLS-1.3

&#x09;	- Encrypt sensitive data with AES-256-GCM

&#x09;	- Stores keys in KMS/HSM - never in code or any env files.



**5. Injection :**

&#x09;- Allows untrusted user input to be sent to an interpreter (e.g. a browser, database, the command line) and causes the interpreter to execute parts of that input as commands without validation.

&#x09;- Application vulnerable if:

&#x09;	- SQL injection : manipulating database queries

&#x09;	- Cross-site scripting(XSS) : Injecting JS into pages

&#x09;	- Commands injection : Executing OS commands.

&#x09;	- LDAP, NoSQL, XPath, Template, and header injection.

&#x09;	- Anywhere strings are concatenated into the parser.

&#x09;- Preventions:

&#x09;	- Use parameterised queries / prepared statements.

&#x09;	- Use ORM that bind values.

&#x09;	- Validate input against of shapes and types.

&#x09;	- Escape output by context (HTML, CSS, JS, URL)

&#x09;	- Apply least privilege.

&#x09;- Scenario : An application's blind trust in frameworks may result in queries that are still vulnerable. For example, Hibernate Query Language (HQL)



**6. Insecure design** :

&#x09;- Focuses on architectural flaws and business logic weaknesses rather than coding implementation errors.

&#x09;- representing different weaknesses, expressed as missing or ineffective control design.

&#x09;- Missing rate limit on sensitive endpoints.

&#x09;- Password reset that doesn't expires tokens.

&#x09;- Workflows that skips steps you assumed were required.

&#x09;- No threat model for new feature.

&#x09;- Trusting that no one would think to do that.



**7. Authentication failure :**

&#x09;- Attacker is able to trick a system into recognizing an invalid or incorrect user as legitimate.

&#x09;- application vulnerable if :

&#x09;	- common passwords are accepted.

&#x09;	- No rate limit on login or password reset.

&#x09;	- Predictable or unsigned session tokens.

&#x09;	- Missing or weak MFA.

&#x09;	- Account enumeration cia different error messages.

&#x09;- Scenario : Credential stuffing, the use of lists of known username and password combinations, is now a very common attack.



**8. Software or data integrity failures :**

&#x09;- failures relate to code and infrastructure that does not protect against invalid or untrusted code or data being treated as trusted and valid.

&#x09;- eg. an application relies upon plugins, libraries, or modules from untrusted sources, repositories.

&#x09;- Vulnerabilities if:

&#x09;	- Auto updates without signature verification.

&#x09;	- Deserializing untrusted JSON/YAML/Java objects.

&#x09;	- CI/CD pipeline that pulls untrusted artifects.

&#x09;	- CDN with no SRI(sub resource integrity) hashes.

&#x09;	- Trusting webhooks without signature checks.



**9. Security logging and alerting failures :**

&#x09;- Without logging and monitoring, attacks and breaches cannot be detected, and without alerting it is very difficult to respond quickly and effectively during a security incident.

&#x09;- vulnerability if:

&#x09;	- No logs on auth failures, access denials, or admin actions.

&#x09;	- Logs that exists but no one reads.

&#x09;	- Sensitive data (passwords, tokens) written into logs.

&#x09;	- Logs stored on the same compromised host.

&#x09;- Scenario: A major Indian airline had a data breach involving more than ten years' worth of personal data of millions of passengers, including passport and credit card data. The data breach occurred at a third-party cloud hosting provider, who notified the airline of the breach after some time.



**10. Mishandling of exceptional conditions :**

&#x09;- when programs fail to prevent, detect, and respond to unusual and unpredictable situations, which leads to crashes, unexpected behavior, and sometimes vulnerabilities.

&#x09;- vulnerabilities if :

&#x09;	- Stack trace returned to the client.

&#x09;	- Fail open code paths that grant access on error.

&#x09;	- Race conditions in error handling.

&#x09;	- Empty catch blocks swallowing errors.

&#x09;- Scenario: Sensitive data exposure via improper handling or database errors that reveals the full system error to the user. The attacker continues to force errors in order to use the sensitive system information to create a better SQL injection attack.
