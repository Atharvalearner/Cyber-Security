Integrated web application security testing tool used to intercept, analyze, modify, and test HTTP/HTTPS traffic between a browser and web server.

* *Browser ⇄ Burp Suite Proxy ⇄ Web Server*



* **Proxy** = intercept HTTP/HTTPS requests, modify requests/responses
* **Repeater** = repeats requests, resend modified requests manually. eg. Tester repeatedly changes payloads.
* **Intercept** = Intercepts a requests or live traffic before reaching server so we can monitor or modify the request
* **Intruder** = brute force tool, automated attacks. eg. Testing passwords automatically.
* **Decoder =** encoding/decoding data
* **Sequencer** = analyze the randomness and predictability of session tokens, cookies, and other sensitive values generated by an application.



**Main Purpose :**

To identify vulnerabilities such as:

&#x09;- SQL Injection

&#x09;- XSS

&#x09;- CSRF

&#x09;- authentication flaws

&#x09;- session issues

&#x09;- file upload vulnerabilities



**Which Burp Suite Features Have You Used** ?

I have mainly used:

1. Proxy to intercept HTTP/HTTPS requests and responses.

2\. Repeater to manually modify and resend requests while testing parameters.

3\. **Interceptor** a requests or live traffic before reaching server so we can monitor or modify the request

3\. Decoder to decode and encode Base64, URL-encoded, and other formats.



**Real Example:** (Very Good in Interviews)

if I want to test a login page for SQL Injection, I intercept the login request using Burp Proxy and send it to Repeater. Then I modify the username or password parameters with test payloads and observe the server response. This helps identify whether the application properly validates user input.



Burp Suite can test **REST APIs, GraphQL APIs, and other HTTP-based services** by intercepting, modifying, and replaying API requests and responses.
